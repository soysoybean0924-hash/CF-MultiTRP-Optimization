## 证据约定与一个具体资源组

`S` 为本轮源码，`R` 为只读存档，`O` 为 MathWorks 当前在线页面明示，`M` 为从代码协方差计算还原的等效信号模型，`?` 为不可见。用户指定的 R2025a URL 本轮无法读取；官方细节只作为**当前页 R2026b 可见证据**，不可声称版本相同，见 [05](05_MathWorks_R2025a.md)。箭头编号 F/M/L 与[图集](11_图集与箭头索引.md)完全相同。所有 `s,x,y` 信号式在 CF Python/旧 MATLAB 中是 **M：模型等效计算**；项目没有调制比特、OFDM 时域样本或真实无线收发器。

先用一位 UE、两个服务 TRP、另一位干扰 UE 理解：取保存的 `results/chasi_formal/b3b_uniform_relative210_seed20261027_20261013/scene_manifest.json`（SHA-256 `d184dd8b541d24306bc7f65d1846a0b4096ce1b22d89a91a965f3fca613a932a`）的**组 g=3，RB 48–63，16 个发射 RB**。组内 `UE 0` 的服务集 `{TRP 0,TRP 1}`，`UE 23` 为 `{TRP 0,TRP 2}`；UE 0 位置约 `(509.016,546.121)m`，UE 23 约 `(500.576,308.927)m`，三个 TRP 均在 `(450,450)m`，它们是**同址不同扇区**，不是三座站。对应 `scenario._geometry:38-52`、`_schedule:87-128`、`generate:219-233`、`solver._effective:75-77`。该保存运行的 Python 源码哈希要以其 `summary.json` 为准，当前工作树代码可能已有变化；这里的服务关系是 R，公式解释是当前 S/M。该图只显示选中的局部链路；其余 18 个 TRP 和组内其他 UE 仍存在，不能据此将真实干扰分母缩成仅 UE 23。

令 `k=UE0,i=UE23,l∈0..20,d=rank`，TRP 0 同时承载两 UE，TRP 1 只向 UE0 发服务流，TRP 2 向 UE23 发流但其无线信号可抵达 UE0。组内每个 UE 的抽象流 `s_i∈C^d` 满足 `E[s_i s_j^H]=δ_ij I_d`。`V_{g,l,i}∈C^{64×d}`，非服务时由 `serve[l,i]=0` 置零；`H_{g,k,l}∈C^{4×64}`。因此

- **F01** `x_{g,l}=Σ_{i∈K_g} V_{g,l,i}s_i∈C^{64}`。代码只存 `V` 并用 `Σ_i||V||²` 算功率；不生成 `x` 样本。`solver.py:47-49,75-77`。
- **F02** `y_{g,k}=Σ_l H_{g,k,l}x_{g,l}+n_{g,k}=Σ_i G_{g,k,i}s_i+n_{g,k}`，`G_{g,k,i}=Σ_l H_{g,k,l}V_{g,l,i}∈C^{4×d}`。同一用户跨服务 TRP 的复振幅**先相加**，然后求功率；`_effective` 的 `einsum('klrn,linq->kirq')` 正是 `l` 求和。`H` 非共轭；接收合并才用 `U^H`。`solver.py:75-77`。
- **F03** 对 UE0，`G_{0,0}=H_{0,0}V_{0,0}+H_{0,1}V_{1,0}` 是有用相干和；`G_{0,23}=H_{0,0}V_{0,23}+H_{0,2}V_{2,23}` 是 UE23 的干扰相干和。其他组内 UE `j≠0,23` 的 `G_{0,j}` 也在求和中。TRP2 不服务 UE0，仍能通过 `H_{0,2}V_{2,23}` 干扰它。距离超过阈值的**非服务**链路被置零，只另记 `omitted_gain` 诊断，不进入 `rates` 分母，见 `scenario.py:227-233`、`evaluate.py:103-110`。
- **F04** `\widehat s_{g,k}=U_{g,k}^{H}y_{g,k}∈C^d` 是等效线性接收关系。项目并未实际生成 `y` 和 `\widehat s`；`_state:94-110` 以协方差直接求 `U`、`E`、`W`。

这里 `g` 是 17 个 SRS 对齐资源组之一，不是 OFDM 子载波；每组一个 `V`，`a_g=tx_rb_count/273`。`k,i` 是**组内** UE 下标，`Resource.users[k]` 才是全局 UE ID。上述 F01–F04 暂省 TTI、RB 内频率/子载波索引，因为代码也未给组内每 RB 一套独立 V。UE 0 与 23 是说明 `serve` 重叠的实际存档选例，不是“只有两 UE 的正式实验”。

## MathWorks 三种方向不能混写

官方[当前可见页面](https://www.mathworks.com/help/5g/ug/evaluate-performance-of-cell-free-mmimo-networks.html)“SRS Processing”“PDSCH Processing”“PUSCH Processing”区分三条链：**上行 SRS**由 CPU 配置 UE，UE→AP；集中模式 AP→CPU 传 path gains/filters，分布式模式 AP 局部估计后传 CSI；CPU 再按服务 AP 的天线行拼 `Ĥ_k^ul`。**下行 PDSCH** CPU 依据 TDD 互易在可见公式中计算 ZF `W_k`；集中模式 CPU 生成预编码波形，AP 中继；分布式模式 CPU 发编码 TB 与 `W_{mk}`，AP 应用矩阵并发送。**上行 PUSCH** 使用 CPU 选择、UL grant 下发的码本 TPMI，集中模式 AP 中继接收波形至 CPU，分布式模式 AP 本地均衡/解调后上送 LLR，CPU 合并与最终检测。TPMI 是 UE 端上行预编码，**不是**下行 `W_k`。官方示例使用全 PHY 和完美 path gains/filter CSI，未模拟 CSI-RS；其 helper 内部代码在本轮不可见，下面不补写其内部算法。三套图见 03–05，官方公式详见 [10](10_MathWorks符号与公式.md)。

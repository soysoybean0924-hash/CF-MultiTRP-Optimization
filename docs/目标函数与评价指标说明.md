# 目标函数与评价指标说明

> 当前修正版口径：`Objective/J_true` 是你要看的 max 主函数，即 `sum b*f(SINR,t)`；`result.Score` 是综合评价分数，用来评价公平性、功率、链路复杂度、惩罚项等工程折中。外层搜索优先最大化 `Objective`，当 `Objective` 几乎相同的时候，再用 `Score` 作为并列辅助评价。

## 0. 当前修正版口径

你最终要看的 max 函数是：

```text
J_true = sum b * f(SINR, t)
```

当前实现中：

```text
f(SINR, t) = t * log2(1 + SINR)
```

当前还没有独立业务权重 `t_k`，所以暂时取：

```text
t = 1
```

因此当前主目标是：

```text
J_true = sum I(any_r b(r,u,g)=1) * log2(1 + SLINR(s,u,g))
```

代码中的分工是：

| 名称 | 当前含义 | 用途 |
|---|---|---|
| `result.Objective` / `Objective` | 当前候选解的主目标值，即 `sum b*f(SINR,t)` | 外层搜索优先最大化的 max 主函数 |
| `BestObjective` | 搜索过程中见过的最大 `Objective` | 外层搜索历史最优主目标 |
| `J_true` | 从最终 `b` 和 `SLINR` 重新计算出的主目标值 | 对齐论文/华为公式的核算值 |
| `result.Score` | 综合评价分数，`benefit - cost - penalty` | 评价公平性、功率、链路复杂度、惩罚项等折中 |
| `proposed.SumRate` | 当前候选解刚计算出的总速率 | 通信结果指标 |
| `result.SumRate` | 存入结果结构体的总速率 | 结果指标 |

当前搜索选择逻辑是：

```text
主排序：max Objective
并列辅助排序：max Score
```

也就是说，最终报告时应该同时给出：

```text
Objective / J_true：主 max 函数结果；
Score：综合评价指标；
Jain：公平性；
ExperienceRate：感知速率；
TrueChannel：鲁棒性；
TotalPower：功率；
ActiveLinks：链路/前传复杂度；
Runtime / InnerConverged：计算效率和内层收敛情况。
```

本文档用于说明当前代码中容易混淆的几个量：`result.Score`、`Objective`、`BestObjective`、`J_true`、`proposed.SumRate`、`result.SumRate`，以及它们和评价指标、结果指标之间的关系。

## 1. 当前最核心结论

当前代码中，外层搜索真正优化的是：

```text
max result.Objective
```

而当前 `result.Objective` 被定义为：

```text
result.Objective = proposed.SumRate
```

所以当前实际优化目标等价于：

```text
max proposed.SumRate
= max result.SumRate
≈ max J_true
= max sum log2(1 + SINR)
```

也就是说，当前版本的主优化目标是纯总速率目标，还没有把功率惩罚、链路惩罚、体验损失惩罚真正纳入外层选优目标。

## 2. 优化目标相关变量

| 名称 | 当前含义 | 当前关系 | 用途 |
|---|---|---|---|
| `proposed.SumRate` | 当前候选解的总速率，所有 UE、RBG、stream 的 `sum log2(1+SINR)` | 当前等于 `result.SumRate` | 结果指标 |
| `result.SumRate` | 把 `proposed.SumRate` 存进最终结果结构体 | 当前等于 `proposed.SumRate` | 结果指标 |
| `result.Score` | 当前候选解的综合评价分数 | 当前等于 `benefit-cost-penalty` | 评价指标 |
| `Objective` | 搜索历史里记录的当前候选主目标值 | 当前等于 `result.Objective` | 搜索日志指标 |
| `BestObjective` | 搜索过程中见过的最大主目标值 | 当前等于历史最大 `result.Objective` | 搜索日志指标 |
| `J_true` | 从最终 `b` 和 `SLINR` 重新计算的主公式目标 | 当前约等于 `result.SumRate` | 主目标验证指标 |

当前可以简化理解为：

```text
当前候选解：
Objective = result.Objective = proposed.SumRate = result.SumRate ≈ J_true

搜索历史：
BestObjective = max(Objective)
```

这里使用“约等于”是因为 `J_true` 是从 `result.b` 和 `result.SLINR` 重新计算得到的验证值，正常情况下应和 `result.SumRate` 一致，但可能存在极小数值误差。

## 3. 为什么当前相等，还要保留多个名字

这些变量当前数值接近相等，是因为代码当前写成：

```matlab
objective = proposed.SumRate;
result.Objective = objective;
result.Score = benefit - cost - penalty;
```

但它们设计上属于不同层级：

| 名称 | 所属层级 | 为什么存在 |
|---|---|---|
| `proposed.SumRate` / `result.SumRate` | 通信结果层 | 表示这个方案最终总速率是多少 |
| `result.Score` | 综合评价层 | 外层搜索在主目标并列时用它辅助判断候选解工程折中好不好 |
| `Objective` | 搜索过程层 | 记录当前这一次候选评价的目标值 |
| `BestObjective` | 搜索过程层 | 记录到当前为止见过的最好目标值 |
| `J_true` | 数学公式验证层 | 从 `b` 和 `SLINR` 重新算，验证是否对应论文/华为公式 |

如果后续把 `Score` 改成综合工程目标，这些量就不会再相等。例如：

```text
result.Score =
    体验速率收益
  + 边缘用户收益
  + 鲁棒真信道收益
  - 功率惩罚
  - 链路/前传惩罚
  - 体验损失惩罚
```

那时：

```text
result.Score      = 综合工程评价分数，用于主目标并列时辅助比较
result.SumRate    = 纯总速率，作为结果指标
J_true            = 按公式重新计算的速率主目标
Objective         = 当前候选解的主目标值
BestObjective     = 搜索到的最大主目标值
```

## 4. 当前代码中的定义链路

在 `cf_evaluate_candidate.m` 中，先计算候选方案的通信指标：

```matlab
proposed = computeMetrics(cfg,scenario,W,bFinal,Q,rankUG,ones(cfg.numUEs,1));
```

在 `computeMetrics` 中：

```matlab
ratePerStream = log2(1+SLINR);
for u = 1:U
    userRate(u) = sum(ratePerStream(:,u,:),'all');
end
metrics.SumRate = sum(userRate);
```

因此：

```text
proposed.SumRate = 所有用户、所有 RBG、所有 stream 的总速率
```

随后在 `computeScore` 中：

```matlab
objective = proposed.SumRate;
score = benefit - cost - penalty;
```

再写入结果结构体：

```matlab
result.Objective = objective;
result.Score = score;
result.SumRate = proposed.SumRate;
```

外层搜索 `cf_search.m` 中使用：

```matlab
result = cf_evaluate_candidate(cfg,scenario,candidate,true);
objective = result.Objective;
score = result.Score;
```

并通过：

```matlab
if objective > t.bestObjective
    t.bestObjective = objective;
    t.bestResult = result;
end
```

选择最优候选解。

## 5. J_true 的含义

`J_true` 在 `cf_compute_true_objective.m` 中计算。

定义为：

```text
J_true = sum I(any_r b(r,u,g)=1) * log2(1 + SLINR(s,u,g))
```

其中：

- `b(r,u,g)` 表示 TRP `r` 是否在 RBG `g` 上服务 UE `u`；
- `SLINR(s,u,g)` 表示 stream `s`、UE `u`、RBG `g` 上的信干噪比；
- 当前没有单独业务权重 `t_k`，所以相当于 `t=1`。

`J_true` 的作用不是重新参与外层搜索，而是验证最终结果是否符合数学公式定义。

## 6. 评价指标

下面这些指标目前不直接决定外层搜索谁赢，而是用于评价方案质量。

| 指标 | 含义 | 用途 |
|---|---|---|
| `MeanRate` | 平均用户速率 | 看整体用户平均水平 |
| `MinRate` | 最差用户速率 | 看有没有用户被严重牺牲 |
| `Rate5` | bottom 5% 用户速率 | 看边缘/弱用户体验 |
| `Rate10` | bottom 10% 用户速率 | 看弱用户群体体验 |
| `Jain` | 公平性指数 | 越接近 1，用户间越公平 |
| `ExperienceRate.MeanExperienceRate` | 掐头去尾后的平均感知速率 | 更接近 3GPP 体验速率口径 |
| `ExperienceRate.EdgeExperienceRate5` | 感知速率 bottom 5% | 对应边缘体验 |
| `TotalPower` | 总发射功率 | 看能耗 |
| `ActiveLinks` | 激活 TRP-UE-RBG 链路数 | 看协同/前传复杂度 |
| `ActiveStreams` | 激活空间流数量 | 看空口与计算复杂度 |
| `RuntimeSeconds` | MATLAB 运行时间 | 看计算效率 |
| `InnerIterations` | 实际内层迭代次数 | 看是否充分迭代 |
| `InnerConverged` | 内层是否收敛 | 判断是不是被 `maxIter` 截断 |
| `InnerStopReason` | 停止原因 | `relative_change` 表示收敛，`max_iter` 表示到达迭代上限 |

## 7. 结果指标

结果指标是最终报告中展示出来的数值，用于描述某个方案最终表现。

常见结果指标包括：

```text
result.SumRate
result.MeanRate
result.MinRate
result.Rate5
result.Rate10
result.Jain
result.TotalPower
result.ActiveLinks
result.ActiveStreams
result.ExperienceRate
result.TrueChannel
result.Robust
result.Edge
result.history
```

其中 `result.SumRate` 是结果指标；当前主优化目标由 `result.Objective` 承担，综合评价由 `result.Score` 承担。

## 8. 华为鲁棒场景指标

华为场景中存在估计信道和真实信道：

| 名称 | 含义 | 用途 |
|---|---|---|
| `scenario.H_est` | 调度器可见的 SRS 估计信道 | 用于调度和波束计算 |
| `scenario.H_true` | 验证用真实信道 | 用于鲁棒性验收评价 |
| `result.SumRate` | 在当前 `scenario.H` 上算的速率，通常对应 `H_est` | 调度侧结果 |
| `result.TrueChannel.SumRate` | 同一组 `b/p/r/W` 放到 `H_true` 上重新算的总速率 | 鲁棒验收更应该看它 |
| `result.TrueChannel.ExperienceRate.MeanExperienceRate` | 真信道下平均感知速率 | 华为体验评价 |
| `result.TrueChannel.ExperienceRate.EdgeExperienceRate5` | 真信道下 bottom 5% 感知速率 | 华为边缘体验评价 |
| `result.Robust.MeanErrorVariance` | SRS 信道估计误差平均强度 | 判断非理想测量程度 |
| `result.Robust.MeasuredFraction` | SRS 实际测量覆盖比例 | 判断测量覆盖程度 |

对于华为最终验收，更应该重点看 `TrueChannel` 下的指标，而不是只看 `H_est` 下的调度侧指标。

## 9. LegacyWeightedScore

代码中还保留了：

```text
result.ScoreParts.LegacyWeightedScore
```

它是旧综合评分：

```text
LegacyWeightedScore = benefit - cost - penalty
```

其中：

- `benefit` 包含总速率、公平性、最小速率、bottom 10% 速率等收益；
- `cost` 包含 active links、total power、active streams 等代价；
- `penalty` 包含最小速率损失、bottom 10% 速率损失、Jain 目标损失等惩罚。

但是当前版本中：

```text
LegacyWeightedScore 只是诊断指标，不参与外层搜索选优。
```

当前外层搜索优先使用：

```text
result.Objective = proposed.SumRate
```

## 10. 建议后续命名

为了避免后续继续混淆，建议逐步把变量命名整理为：

| 建议名称 | 含义 |
|---|---|
| `J_rate` | 纯速率目标，`sum log2(1+SINR)` |
| `J_score` | 综合工程评价分数，用于主目标并列时辅助比较 |
| `SumRate` | 总速率结果指标 |
| `Jain` | 公平性评价指标 |
| `ExperienceRate` | 感知速率评价指标 |
| `TrueExperienceRate` | 真信道下感知速率 |
| `TotalPower` | 功率结果指标 |
| `ActiveLinks` | 协同链路复杂度指标 |

当前 `result.Score` 已用于综合工程评价：

```text
Score =
    体验速率收益
  + 边缘用户收益
  + 鲁棒真信道收益
  - 功率惩罚
  - 链路/前传惩罚
  - 体验损失惩罚
```

这样 `Objective/J_true` 负责主 max 函数，`Score` 负责综合评价，`SumRate`、`Jain`、`Power`、`ActiveLinks`、`ExperienceRate` 则作为结果和证据指标报告。

# 7 个入口代码的递进关系说明

这组代码不是七套彼此无关的物理模型，而是沿着同一条研究路线逐层增加能力：

```text
基础 Cell-Free
  → 加入 SLINR/WPS 和波束迭代
  → 在内层模型外加入 GA
  → 将外层替换为 PSO
  → GA 后接 PSO
  → PSO 后接 GA
  → GA 与 PSO 机制在单次更新中融合为 PGSAO
```

所有外层算法都调用相同的 `cf_evaluate_candidate.m`。因此比较搜索算法时，信道、内层模型、指标、Score 和评估预算保持一致，改变的只是“如何在 9 维策略空间中提出下一个 candidate”。

## 1. `run_01_basic.m`：基础 Cell-Free 模型

这是整个研究链条的起点，实现最基本的 `H → b/r → W → p → SINR/Rate`。

主要过程：

1. `cf_generate_scenario` 固定生成 DU/UE 位置和信道 `H`；
2. 每个 UE/RBG 按信道增益选择最强的若干 DU，形成 `bInit`；
3. 基础入口将 `maxRank=1`，所以每个 UE/RBG 使用 1 个数据流；
4. 波束 `W` 使用 MRT 初始化；
5. 对每个 DU/RBG 的所有波束做功率归一化；
6. 由 `p(r,u,g)=Σ_s||W(:,s,r,u,g)||²` 得到链路功率；
7. 计算用户速率、Jain 公平性、活跃链路和总功率。

这一版没有波束迭代，也没有外层搜索。它回答的是：“基础多 DU 协同服务多 UE 的链路能否正确跑通？”

## 2. `run_02_inner_wps.m`：相对基础版增加内层优化

与 `run_01_basic.m` 相比，信道和基础调度框架不变，新增以下内容：

- `r` 不再强制为 1：根据聚合信道 SVD 和 `rankThreshold` 在 1/2 流间选择；
- 为每个接收流建立合并向量 `Q`；
- 显式计算每流有用信号、流间干扰、用户间干扰和 `SLINR`；
- 计算 `WPS=delta_u·ln(1+SLINR)`；
- 迭代更新辅助变量 `zeta`；
- 用 `alpha=1/(p+epsilon)` 对弱功率链路施加更强稀疏惩罚；
- 用 `lambda` 控制链路/空间负载，用 `mu` 控制 DU–RBG 功率；
- 通过线性方程更新 `W`，再做功率归一化；
- 增加最低服务保护和相对 Baseline 的弱用户修复。

因此这一版回答的是：“在固定策略参数下，能否沿 `H → W → SLINR → WPS → W` 对波束和资源状态进行内层迭代？”

## 3. `run_03_ga.m`：相对内层版增加 GA 外层搜索

`run_02_inner_wps.m` 只评估一个固定 candidate；`run_03_ga.m` 在它外面增加遗传算法，搜索：

1. PF 指数；
2. 候选 DU 数；
3. `p→b` 调度门限；
4. 链路惩罚；
5. 功率惩罚；
6. 最大 rank；
7. rank 判定门限；
8. 弱用户修复功率；
9. 最多修复链路数。

GA 的新增机制为：随机种群、锦标赛选择、精英保留、交叉、变异。每个个体都要完整调用一次内层模型，最终用综合 Score 作为适应度。

关键理解：GA 不直接逐元素搜索巨大张量 `b/p/r/W`，而是搜索生成和优化这些变量的高层策略参数。这样把不可承受的原始维度压缩为 9 维策略空间。

## 4. `run_04_pso.m`：相对 GA 只替换外层搜索机制

物理模型、9 维编码、内层迭代和 Score 均不改变。变化仅发生在 candidate 如何更新：

- GA 依靠选择、交叉、变异；
- PSO 为每个 candidate 增加速度 `V`；
- 保存每个粒子的历史最好位置 `pbest`；
- 保存全体历史最好位置 `gbest`；
- 由惯性、自我认知和社会认知共同更新位置。

PSO 通常具有较快的连续空间收敛速度，但可能较早聚集到局部区域。离散参数仍由归一化位置解码为整数或类别。

## 5. `run_05_ga_pso.m`：相对纯 PSO 增加 GA 前置阶段

这一版不是同时混合，而是顺序执行：

```text
前半评估预算：GA 全局探索
后半评估预算：把 GA 最终种群交给 PSO 局部精修
```

相对 `run_04_pso.m`，PSO 不再从完全随机粒子开始，而是从 GA 已探索出的种群开始。设计意图是利用 GA 保持多样性，再利用 PSO 快速向较优区域收敛。

## 6. `run_06_pso_ga.m`：相对 GA→PSO 交换阶段顺序

执行顺序改为：

```text
前半评估预算：PSO 快速定位有希望的区域
后半评估预算：把 PSO 的 personal-best 种群交给 GA
```

后段 GA 通过交叉和变异重新增加种群多样性，尝试跳出 PSO 可能形成的局部聚集。它与 GA→PSO 的主要差别不是算子种类，而是“探索”和“开发”出现的先后次序。

## 7. `run_07_pgsao.m`：相对两阶段混合改为单阶段有机融合

GA→PSO 和 PSO→GA 都是在两个阶段分别运行算法。PGSAO 则在每个粒子的同一轮更新中融合二者：

1. 当前个体与随机同伴做均匀交叉，提供群体多样性；
2. 与自身 `personal best` 交叉，引入自我认知；
3. 与全局 `global best` 交叉，引入社会认知；
4. 额外产生变异后代；
5. 只用评估结果最好的后代替换当前个体。

因此 PGSAO 不是简单地“先跑 GA、再跑 PSO”，而是用 GA 的交叉/变异形式实现 PSO 的个人和群体引导。

## 哪些代码在七个入口之间始终不变

| 共享文件 | 作用 |
|---|---|
| `cf_default_config.m` | 系统规模、功率、内层参数、Score 权重和搜索预算 |
| `cf_generate_scenario.m` | 固定位置与信道，保证算法在同一 H 上比较 |
| `cf_decode_candidate.m` | 将 `[0,1]^9` 解码为连续/离散策略参数 |
| `cf_evaluate_candidate.m` | 生成和优化 `b/p/r/W`，计算指标与 Score |
| `cf_search.m` | 实现五种外层搜索方式 |
| `cf_plot_result.m` | 统一结果图，避免不同算法使用不同绘图口径 |

## b、p、r 图应该怎样理解

- `b` 是二值链路变量；图中对 RBG 求和后只能出现整数 `0…G`，所以使用离散颜色。
- `r` 是数据流数，只能出现整数 1、2，使用离散颜色。
- `p` 是连续功率，0.5 等小数具有实际意义，使用连续颜色。
- 三张图的坐标刻度位于色块中心，但不再开启默认网格；边界线画在半整数位置，因此不会穿过色块中心形成十字。

## 公平比较五种搜索算法时应固定什么

必须固定：场景随机种子、`H`、内层最大迭代次数、Score 权重、种群规模和最大 candidate 评估次数。代码使用 `maxEvaluations` 而不是只比较“迭代代数”，因为 PGSAO 每个个体可能产生多个后代，只有统一实际评估次数才更公平。
